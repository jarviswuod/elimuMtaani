| DEC-015 | **Game-based learning is a second optional branch, library-first.** Like the audio branch, it checks for something pre-made first (a general-purpose game library) and only generates a new game when nothing fits. | DEC-016 | **The "real game" bar is schema-enforced.** Every game — library or generated — must carry non-empty `mechanics: {turns, challenge, winCondition}` and pass a classroom-materials allowlist. Validation failure → one named-violation retry → fall back to the closest library entry. | The difference between game-based learning and a worksheet wearing a game label must be testable, not aspirational. | 2026-09-02 |
| DEC-017 | **The understanding gate is a whole-class teacher judgment; the system prepares, never tracks.** A topic ends with a short quiz; the teacher decides ready/not-ready; "not yet" loops through review or a game replay (zero model calls) to a re-quiz; the next topic unlocks only on her call. Only aggregate stand-in scores + the judgment are stored — never any individual learner's answer. Extends (does not replace) Sprint 001's revisit-merge escape hatch. | Strand mastery is built topic by topic; gate strictness is a teaching judgment the system supports, not overrides (Q-007). Preserves R1/no-learner-data structurally. | 2026-09-02 |
| DEC-018 | **Games are teacher-facilitated and classroom-only, permanently.** No digital surface a learner touches; chalkboard, teams, physical space, oral scoring. Any game concept requiring learner login or per-learner recording is out of scope in every sprint, not just this one. | Carries the founding privacy constraint into the game branch as a structural property. | 2026-09-02 |
